**The one open risk in today's build, and how far it was actually narrowed.**
`check-drift.js` compares a rendered frame against a committed PNG, so it is
only as sound as the rendering being reproducible. Three axes were considered
and two were measured:

1. *Same browser, same tree.* Exact — **0 changed pixels of 81,095 across all
   seven frames** on an immediate re-run.
2. *Headless-shell against full Chromium* (the sandbox's `local-snapshot.sh`
   path uses `chromium_headless_shell-1194`; CI's bare `chromium.launch()`
   does not). Re-ran the whole set against
   `/opt/pw-browsers/chromium-1194/chrome-linux/chrome`: **also 0 px on all
   seven**, `map-summer-day` included, which is the frame carrying rendered
   text and dashed borders and therefore the likeliest to differ. So the
   headless-mode axis is closed.
3. *Build 1194 against build 1148* (the sandbox's pre-staged binary against
   the repo's pinned Playwright, which CI installs). Not measurable in the
   sandbox — the 1148 download is blocked here — so it was measured by the
   first CI run instead, and it is **real**: five frames bit-identical,
   `map-summer-day` **1327 px** (every glyph of its rendered labels, and
   nothing else in the frame), `inside-winter-day` **48 px** (a band inside
   the firebox, where the flame is drawn with gradients). Both report pictures
   are in the record at
   `previews/2026-09-04-afe1338-drift-{map-summer-day,inside-winter-day}.png`.

Raising `DRIFT_FAIL_PIXELS` was the obvious response and the wrong one: no
channel tolerance can separate a re-antialiased glyph from a moved one, and a
threshold above 1327 would hide every real change smaller than the whole map
chip. So `0e3d877` removed the cross-environment comparison instead — see
Build & deploy. `DRIFT_CHANNEL_TOL` and `DRIFT_FAIL_PIXELS` remain
env-settable, but they are now the second answer, not the first.

**Consequence worth knowing, and not a fault:** the in-session run now
compares a sandbox render against CI's kept frames, so it carries a standing
floor of browser noise that CI does not. The report picture is what
distinguishes them — noise strikes every glyph of a label at once; a real
change strikes a shape.

**One founder-attention item, and it is a pre-existing race this day happened
to trip.** The first `wait-for-deploy.sh` run on the writeup commit **timed
out at 10 minutes**, and the run for the middle commit `0e3d877` is recorded
as a **failure** — but neither is a deploy fault:

- `concurrency: pages` with `cancel-in-progress: false` serialises runs, so
  three pushes in one hour queue behind each other. `0e3d877`'s screenshot job
  did not start until 00:35 and the writeup was pushed at 00:36, so the
  writeup's own run only began at 00:43. The 10-minute poll was measuring the
  queue, not a failure; a second poll found the preview at once.
- `0e3d877`'s failure is its **"Commit screenshots if changed"** step, which
  failed instantly at 00:43:42. Every step before it succeeded, drift step
  included. The screenshot job checks out `ref: main` and pushes the bot
  commit back, so once `9d663cf` was on `origin/main` that push was a
  non-fast-forward and was rejected. The cost is that `0e3d877` has no preview
  set and never will — the same shape of loss the 2026-08-04 note records for
  far-keeper's cancelled camera, from a different cause.

**Nothing here needs mending in the workflow today**, and it would be wrong to
guess at a fix on one occurrence: the race only bites when a second commit is
pushed while a screenshot job is mid-flight, which the normal two-commit day
avoids by waiting on `wait-for-deploy.sh` between them. Today had three
commits and the second push went out during the queue. The lesson is
operational and belongs to the agent, not the YAML: **wait for the preview of
each commit before pushing the next one, even when the second commit is
small.** If a future day wants to make the workflow robust to it anyway, the
shape would be a `git pull --rebase` before the bot's push — but `pages.yml`
is a carve-out on the deploy path and that is a change to make deliberately,
not in the tail of a session.
